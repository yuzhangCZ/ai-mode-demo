## 3. 端/云部署切分图

```
┌─────────────────── 云端（账号绑定）───────────────────┐
│                                                        │
│  推理上下文（会话期临时）         长期记忆（持久化）       │
│  ┌─────────────────────┐      ┌────────────────────┐  │
│  │ WeLM 主模型           │      │ memory-manager 写入 │  │
│  │ ＋ 清单/reference     │      │ get_memory 读取     │  │
│  │ ＋ 技能返回结论        │      │ （含聊天记录摘要）    │  │
│  └─────────────────────┘      └────────────────────┘  │
│  └─────────────────────┘                                │
│  技能执行大脑（元素树解析/动作规划/游戏API）                │
└───────────────△──────────────────────△─────────────────┘
                │ 指令下行        状态上行
┌───────────────┴──────────────────────┴─────────────────┐
│                    端侧（手机本地）                       │
│  薄执行器: 无障碍操作执行·手势渲染（零智能·断网即全灭）      │
│  会话记录: 本地存储·换设备不跟随                           │
│  聊天卡片: 客户端渲染（断网残留属客户端缓存）                │
└─────────────────────────────────────────────────────────┘
```

**要点**：大脑全云、手脚在端、记忆分家——蒸馏摘要上云，原始对话留端。

## 4. 技能调用与工具组织图

```
主模型上下文（常驻部分）
├── 基础工具层（4 个，schema 常驻）
│     ├── read_skill      ── 进入技能注册表的唯一通道
│     ├── get_memory      ── 读长期记忆（按需检索）
│     ├── general_search  ── 联网搜索（source 参数，如 "miniapp"）
│     └── get_position    ── 定位
│
└── 技能清单 references/_skills_index.md
      │ 每条含：分类·中文名·一句话概述·召回关键词·加载文档的 JSON 参数
      │ 首次使用某技能时
      ▼
     reference（references/能力描述.md，五段式：
       是什么／能做什么✅／不支持什么❌／易混淆区分／用户常见问法）
      │
      ▼
     调用入口（技能 slug 与调用工具名可分离：mini-app ↔ operate_miniapp）
      │
      ▼
     技能执行（子代理模式：主模型只见结论，不见过程）

用户扩展（与注册表隔离）
└──「小工具」技能＝调度器 ──► 用户实例（记账/打卡…）
                            · 动态创建 · 个人命名空间 · 数据持久
                            · 不进技能清单、无系统级 slug
```

## 5. 架构分层职责一览表

| 层 | 位置 | 职责 | 已确认关键事实 |
|---|---|---|---|
| 模型层 | 云 | 理解/决策/生成 | WeLM 主控（人格统一）；子模型按需工具式协作（单问上下文） |
| 路由层 | 云（模型侧） | 选技能 | 清单粗路由→read_skill 懒加载→精确调用；模型路由另走系统预设策略 🟡 |
| 能力层 | 云 | 封装执行 | 胖技能（内聚检索/计算/聚合）返回可读结论；子代理模式（mini-app＝域受限自治 GUI 子代理） |
| 执行层 | 云脑＋端手 | 落地操作 | 三通道：元素树（小程序）/原生接口（wx-action）/专属协议（游戏） |
| 记忆层 | 云 | 状态保持 | 双系统（agent 显式/平台行为）；读写不对称；摘要持久化 |
| 呈现层 | 端 | 用户界面 | 卡片＝工具返回负载原样转发；步骤卡＝执行进度实时转述 |
| 会话层 | 端 | 历史存储 | 本地存储·换设备断·上下文临时 |

## 6. 与供给侧文档的关系

```
供给侧文档（愿景层）:  原子接口 ──── 原子卡片 ──── GUI 操作
                        ✗            ✗            ✓
黑盒实测（运行层）:  （契约层不存在）（实际＝工具返回负载）（元素树形态·唯一主力）

结论: 文档画的声明式原子能力是愿景层；
      实际运行 ＝ 通用元素树自动化 ＋ 特殊域协议通道
```
